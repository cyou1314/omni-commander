# Can 使用教程（从零装一遍，到日常使用）

这份教程把 Can 从零装起来、接上网页版 AI、再到日常怎么用，一步一步写全。
每一步后面都有「验收」——过了再往下走，出问题先看第 7 步故障排查。

Can 分三段，装的顺序也是这个顺序：

1. **网关**：跑在一台小服务器上，负责验身份、转发任务（第 1 步）；
2. **agent**：装在你的 Mac 上，负责真干活（第 2 步）；
3. **入口**：在 ChatGPT / Claude 网页版里把 Can 加为连接器（第 3、4 步）。

> 教程里的地址一律写成 `https://你的网关域名` 这样的占位符，照着换成你自己的。
> 文中出现的密钥、机主码只写名字和用途，**永远不要把真值写进任何文档或聊天里**。

---

## 第 0 步 — 准备

你需要先备齐这些：

- **一台小服务器**（云主机、家里的常开机器都行），能跑 Python、能被公网访问。
  网关很轻，配置不挑。作者用一台小 VM + ngrok 免费域名跑通至今。
- **一个公网 HTTPS 地址**指向这台服务器的网关端口。办法任选：
  ngrok（免费域名即可）、你自己的域名 + 反向代理（Caddy/Nginx）、Cloudflare Tunnel 等。
  AI 那边只认 HTTPS，裸 IP + 自签证书不行。
- **一台 Mac**（agent 先在这上面跑；Windows 版代码有、还没真机验过，见附录 B）。
- **Node**：agent 是零依赖的 Node 脚本，借用你机器上已装的 Node 运行。
  作者机器上是 Node 26 + 自装目录 `~/node`，版本较新即可。
- **一个 ChatGPT 账号**（Plus 已验；这是你跟电脑说话的第一个入口），
  或者 Claude 账号（免费版已验可装）。
- **心理预期（重要）**：装的过程中要给 Can 两个 macOS 系统权限——
  「辅助功能」（让它能点按钮、打字）和「屏幕录制」（让它能截图看屏幕）。
  这是桌面操控的必经之路，权限给的是 **Can.app 本身**，不是某个来路不明的程序。

**验收**：服务器能从公网用 HTTPS 打开（哪怕先是个空白页）；Mac 上 `node --version` 有输出。

## 第 1 步 — 部署网关

网关的全部代码就是 `gateway/gateway.py` 一个文件。

### 1.1 把代码放上服务器

把仓库的 `gateway/` 目录拷到服务器上（比如 `~/can-gateway/`），准备 Python 环境：

```bash
cd ~/can-gateway
python3 -m venv .venv
./.venv/bin/pip install "mcp<2"
```

注意 `mcp` 要钉在 2 以下，网关代码按 1.x 写的。

### 1.2 写 .env（网关的全部配置）

在 `gateway.py` 同目录建 `.env`，权限收紧到只有自己能读：

```bash
chmod 600 .env
```

里面是这些变量（**只写变量名，真值你自己生成、自己保管**）：

| 变量 | 用途 |
|------|------|
| `CAN_PUBLIC_URL` | 网关的公网地址，如 `https://你的网关域名`（结尾不要带 `/`）。授权页、回调地址都按它拼，写错了授权会失败 |
| `CAN_OWNER_CODE` | **机主码**：你自己定的一串足够长的随机字符。每次有新 AI 入口要连你的电脑，授权页会让你输它——这是「只有机主本人能授权」的钥匙 |
| `CAN_AGENT_KEY` | agent 和网关之间的共享暗号。agent 那边的配置里要填同一个值；两边对不上，agent 连不上来 |
| `CAN_AGENT_TTL` | 可选，默认 45（秒）。agent 多久没心跳就算离线，工具调用会如实返回离线 |
| `CAN_PORT` | 可选，默认 8792。网关监听端口 |
| `CAN_STATIC_CLIENT_ID` / `CAN_STATIC_CLIENT_SECRET` | 可选。给不支持「动态注册」的连接器预留的固定客户端，一般用不上；ChatGPT 和 Claude 都走动态注册，留空即可 |

### 1.3 让它常驻（systemd 示例）

用 systemd 托管，崩了自动拉起、开机自启。两个服务：一个跑网关，
一个跑隧道（这里以 ngrok 为例，你用别的公网方案就换成你自己的）：

```ini
# can-gateway.service
[Unit]
Description=Can gateway
After=network.target

[Service]
Type=simple
WorkingDirectory=/你的路径/can-gateway
EnvironmentFile=/你的路径/can-gateway/.env
ExecStart=/你的路径/can-gateway/.venv/bin/python /你的路径/can-gateway/gateway.py
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

网关跑起来后，它还会在同目录生成/使用这些运行时文件（**都不要提交进任何仓库**）：
`.env`（密钥）、`state.json`（已注册的客户端和令牌，权限 600）、
`traffic.log` / `tool-calls.log`（流量与调用日志，排查问题时看它们）。

> 作者的部署还多了一层保险：一个每分钟跑一次的看门狗脚本，
> 万一服务器被整体重启/替换、服务文件丢了，它会把服务重新装好拉起来。
> 2026-11-06 真实经历过一次服务器重启，约 2 分钟自愈，Mac 那头自动重连。
> 这是可选加固，不是必需。

**验收**：

- 浏览器打开 `https://你的网关域名/`，能看到 Can 的落地页（产品名 + 图标）；
- 没带令牌直接请求 `https://你的网关域名/mcp` 应返回 401——能返回 401 说明门锁是好的；
- `systemctl status can-gateway` 是 active，重启服务器后能自己起来。

## 第 2 步 — 在 Mac 上装 agent

agent 由三部分组成，都在仓库里：

- `agent/agent.js` —— 本体（零依赖 Node 脚本，四层能力都在里面）；
- `helper/` 编出来的桌面引擎二进制（文件名就叫 `Can`）—— 桌面层靠它干活；
- `app/supervisor.swift` 编出来的 **Can.app** —— 守护进程的外壳：
  launchd 先拉起它，它再拉起 Node 跑 agent.js。
  这么绕一层的原因是 macOS 的权限记账方式：进程链顶端是 Can.app，
  辅助功能/屏幕录制就都记在「Can」名下，而不是记在 Node 头上。

### 2.1 放文件

在 Mac 上建数据目录，把东西放进去：

```bash
mkdir -p ~/can-agent
# 把 agent.js、编译好的桌面引擎（Can）放进 ~/can-agent/
# 把 Can.app 放进 ~/Applications/
```

注意分工，装错地方后面会踩坑：

- **`~/can-agent/`** 是数据目录：`agent.js`、引擎、配置和日志都住这里，随便更新；
- **Can.app 的包内容装好后就冻结，不要再往里面加/改任何文件**——
  包内容一变，它的签名指纹就变，第 2.3 步给的系统权限会全部失效要重来。

### 2.2 写 config.json

在 `~/can-agent/config.json` 里写（同样收紧权限 `chmod 600`）：

```json
{
  "gateway": "https://你的网关域名",
  "agentKey": "和网关 .env 里 CAN_AGENT_KEY 同一个值",
  "name": "Can agent (Mac)",
  "workRoot": "/Users/你的用户名/can-work",
  "cuaPath": "/Users/你的用户名/can-agent/Can",
  "fence": { "confirmRun": true, "confirmEgo": true, "confirmDesktop": true }
}
```

字段说明：

| 字段 | 用途 |
|------|------|
| `gateway` | 网关的公网地址，和 `CAN_PUBLIC_URL` 一致 |
| `agentKey` | 与网关共享的暗号，两边必须一字不差 |
| `name` | 这台 agent 的显示名，随意 |
| `workRoot` | **工作文件夹**：文件类工具只能在这个文件夹里活动，进不来出不去。先建好这个文件夹。仓库示例配置里的路径是作者本机的，自己装务必改成你的 |
| `chromePath` | 可选。干净 Chrome 层的 Chrome 路径，装在标准位置就不用填 |
| `cuaPath` | 桌面引擎二进制的路径（字段名是历史遗留，填自研引擎 `Can` 的路径即可） |
| `fence` | 安全围栏开关，第 6 步细讲。**新装请保持三个都为 true** |

### 2.3 给两个系统权限（这一步最容易卡，照着做）

打开「系统设置 → 隐私与安全性」，给 Can 两项权限：

1. **辅助功能**：进「辅助功能」列表，找到带三角图标的 **Can**，把开关打开。
   - 列表里引擎第一次运行时会自己把条目注册进来；
   - 如果列表里出现两个 Can：**带三角图标的才是正主**，
     另一个黑图标的是引擎文件的旧条目，别开错。
2. **屏幕录制**：这一项引擎自己弹的申请**不会**把条目加进列表（2026-11-06 实测结论）。
   可靠做法：在「屏幕录制」列表点右下角的「＋」，在文件选择器里选
   `~/Applications/Can.app` 添加进来——用「＋」加进来的条目默认就是开启状态。

两个都给完后，**重启一次 agent** 权限才生效：

```bash
launchctl kickstart -k gui/$(id -u)/com.can.agent
```

（launchd 的 plist 参考 `agent/com.can.agent.plist`，注意把里面的程序路径
换成你机器上的实际路径——现行装法是让 launchd 拉起 Can.app 里的守护进程，
再由守护进程拉起 Node。）

### 2.4 启动并确认连上

plist 放进 `~/Library/LaunchAgents/` 后 bootstrap 启动（或重启 Mac，它会自启）。
agent 每 20 秒向网关报一次心跳，状态写在同目录的 `status.json` 里。

**验收**：

- `~/can-agent/status.json` 显示已连接；
- 服务器上看 `tool-calls.log` / `traffic.log`，能看到这台 agent 的心跳；
- 两个权限列表里，Can 的开关都是开的（图标认带三角的那个）。

## 第 3 步 — 接 ChatGPT（第一个入口）

在 ChatGPT 网页版里把 Can 加为连接器：

1. 打开 ChatGPT，进设置里的插件/连接器管理，选「添加自定义连接器」；
2. 名称填 `Can`，服务器地址填 **`https://你的网关域名/mcp`**（注意结尾的 `/mcp`）；
3. 保存后点「连接」，浏览器会跳到 **Can 自己的授权页**——
   页面上会写明是哪个应用在请求连接，并让你输入**机主码**；
4. 输对机主码、点授权，跳回 ChatGPT，连接器显示已连接。

这套流程就是 OAuth 2.1：ChatGPT 自动在网关注册、走授权码流程，
网关只认「机主码对了」才发令牌。令牌过期会自动续，不用你管。

> **铁律：网关那边增删了工具，必须回连接器管理里点一次「刷新工具」。**
> ChatGPT 记的是添加那一刻的工具清单，不刷新，新工具永远不出现——
> 这是装完之后最常见的「为什么没有那个功能」。

**验收**：新开一个对话，先确认 Can 连接器的开关是开的，然后说一句：
「用 Can 看一下我的电脑在不在线」——它调用 `can_status`，
回你电脑名和系统版本，就算全线打通。

## 第 4 步 — 接 Claude 网页版（第二个入口，可选）

流程和 ChatGPT 几乎一样（2026-11-06 在免费账号上实测通过）：

1. Claude 网页版 → 设置 → 连接器 →「添加自定义连接器」；
2. 名称 `Can`，地址同样是 `https://你的网关域名/mcp`；
3. 点「连接」，跳到 Can 授权页，输机主码授权，跳回后显示「已连接到 Can」；
4. 连接器详情里能看到 33 个工具。

和 ChatGPT 的一个区别：**Claude 这边每个工具默认是「需要批准」**，
也就是每次调用前它会先问你一下。这是 Claude 的默认策略，不用改也能用，
嫌烦可以在它的连接器设置里调整。

每个入口都是独立授权的：以后想断开哪家，在那家的连接器管理里删除/断开即可，
或者在网关侧吊销它的令牌，不影响其他入口。

**验收**：在 Claude 的新对话里让它调一次 `can_status`，能报出你的电脑在线即通。

> 豆包的情况单独说明：网页版的「新建自定义连接器」是灰的（提示去电脑版建）；
> 电脑版能建、能存，但安装时会被「本地电脑未初始化」挡住——
> 它依赖的本地组件目前只有 Windows 版，**Mac 上这条路暂时走不通**，不用浪费时间试。

## 第 5 步 — 日常使用

接通之后，用法就是**在对话里用正常说话的方式交代事情**。
下面按四层各给几个真实例子（都是实际跑通过的用法）：

### 5.1 文件与终端

- 「看一下工作文件夹里有什么，把最新的那个文件读给我听」
- 「在工作文件夹里新建一个 `本周备忘.txt`，把刚才聊的三条写进去」
- 「跑一下命令看看磁盘还剩多少空间」

规矩：文件工具只在第 2 步设的**工作文件夹**里活动——绝对路径、跳出去的路径、
符号链接逃逸都会被拒；读文件上限 256KB、二进制文件不读；
`can_write_file` 只新建、**拒绝覆盖**已有文件；
终端命令固定在工作文件夹里跑、30 秒超时、输出有截断。
（没有删除文件的工具，这是有意的：删除属于停手边界。）

### 5.2 干净 Chrome（没有登录状态的浏览器）

- 「打开 example.com，看看页面标题是什么」
- 「去这个公开网页把正文读给我」

它用一套独立的浏览器配置，**不带你的任何登录**，适合查公开资料、打开陌生链接。
页面是按「结构快照」读的——元素带编号，点击/输入都按编号来，比看图猜坐标稳。

### 5.3 日常浏览器 ego（带你的登录状态）

- 「去 X 看一下我的主页，粉丝数是多少」
- 「在我常逛的那个站里搜一下这个关键词，把前三条标题读给我」

这一层开的是你天天用的浏览器，但干活在一个名叫 **「Can」的专属任务空间**里，
不碰你自己开着的标签页；任务空间建在你日常用的浏览器配置下，才会带着你的登录
（建错配置会是未登录状态，这是 V1 阶段就验过的结论）。

### 5.4 桌面软件

- 「打开计算器，算一下 7 乘 6」（结构快照读到显示屏数字来验算）
- 「打开备忘录，新建一条笔记，把刚才的结果写进去」
- 「截一张全屏图给我看看现在屏幕上是什么」

桌面层先读窗口的**结构**（按钮、输入框都带编号），按编号点和输；
遇到结构读不出来的界面（画布类、自绘类），还有像素兜底：
窗口截图、区域放大（zoom）、按坐标点和拖。
**截图结果会直接显示在对话里**（ChatGPT 里点图可以全屏看），不用另外发文件。

### 5.5 批量工具：慢任务的提速关键

一步一往返地遥控电脑是很慢的，所以有三把「一次下令、连做多步」：

| 工具 | 用途 |
|------|------|
| `can_batch` | 跨层混编：一次调用里串起最多 10 步不同工具（比如：查状态→读文件→跑命令→写文件），在 agent 本地一口气执行完 |
| `can_ego_batch` | 在 ego 里连做最多 12 步（打开→快照→点→输→等），只付一次浏览器启动的开销 |
| `can_desktop_batch` | 在桌面层连做最多 12 步，可以先单独看一次快照、再照着元素名字批量点 |

你不用记这些工具名——直接在对话里把一串步骤一次说完，
大脑自然会优先用批量工具把它们打包。步骤之间有先后依赖、需要看一眼结果再决定的，
就拆开说，别硬打包。

### 5.6 一次完整的跨层任务长什么样

V1 阶段固化下来的验收任务（`workflows/01-x-profile-to-notes.md`）就是个好例子：

> ego 打开我的 X 主页读到粉丝数 → 写进工作文件夹的文件并读回确认 →
> 在备忘录里新建一条笔记把数字写进去 → 再读回来核对。

四层里用上三层、每一步都有回读验证——这也是给 Can 派活的推荐姿势：
**让它做完一步读回一步，比一口气全干完再汇报可靠得多。**

## 第 6 步 — 安全围栏怎么调

围栏在 agent 本机执行，配置在 `~/can-agent/config.json` 的 `fence` 段，
改完重启 agent 生效。三个开关（代码里**默认都是开**）：

| 开关 | 管什么 |
|------|--------|
| `confirmRun` | `can_run_command` 跑终端命令前 |
| `confirmEgo` | 在日常浏览器（带登录）里点击、输入前 |
| `confirmDesktop` | 在桌面软件里点击、输入、按键前（不填时跟随 `confirmEgo`） |

- **开（true）**：每次敏感动作，电脑屏幕上会弹一个原生对话框，
  写明要干什么，你点「允许」才执行；拒绝、取消、60 秒超时都按拒绝处理。
  另外有个信任窗口 `fence.trustWindowMin`：批准一次后 N 分钟内不再弹（默认 0 = 每次都问），
  还有一小时内敏感确认次数的上限（30 次）防失控。
- **关（false）**：不弹窗，直接执行，快，但大脑被带偏时没有人在中间拦一道。

**作者本人的取舍**：日常用下来每次确认太拖节奏，他把三个都关了（全免确认）。
他敢关的前提是下面两条还在——这两条**任何设置都关不掉**：

1. **灾难命令硬名单**：`sudo`、`rm -rf`、往根目录删、关机/重启、格式化/擦盘、
   把命令管道喂给 shell、杀进程类命令等，命中就直接拒绝执行，不弹窗、不商量；
2. **全量审计**：每次工具调用、每次放行/拦截都追加写进 `~/can-agent/audit.log`
   （一行一条 JSON）。想复盘「它到底干了什么」，让对话里的 AI 调 `can_audit_log`
   读，或者自己在电脑上打开这个文件看。

**给新装的人的建议**：先全开着用几天，确认它的行为符合预期，再按层逐个放宽；
日常浏览器那一层（`confirmEgo`）建议长期开着——那层带着你的真实登录，
误点一次的代价比其他层大。

另外一条边界不在配置里，是规矩：**验证码、二次验证、付款、删除、正式发布**，
这类事 agent 不做，到了这一步它会停下来交回给你本人。

## 第 7 步 — 故障排查

### 7.1 对话里找不到 Can 的工具 / 新工具不出现

十有八九是没刷新：去那家 AI 的连接器管理里对 Can 点**「刷新工具」**
（ChatGPT）；Claude 侧检查连接器开关是否打开、必要时新开一个对话。
网关每增删一次工具，每个入口都要各刷一次。

### 7.2 工具回「agent_offline」/ 电脑不在线

按顺序查三段，哪段断了修哪段：

1. **Mac 上的 agent**：看 `~/can-agent/status.json` 和 `agent.log`；
   进程不在就 `launchctl kickstart -k gui/$(id -u)/com.can.agent` 拉起来；
2. **网关**：服务器上 `systemctl status can-gateway`，不活就重启服务，
   再看 `traffic.log` 尾巴有没有报错；
3. **公网通道**：浏览器打开 `https://你的网关域名/` 看落地页出不出来——
   出不来是隧道/域名的问题（ngrok 进程、域名解析、反向代理配置）。

判断标准：agent 超过 45 秒没心跳，网关就如实说离线，它不会假装执行——
所以「离线」这个回答本身是可信的。

### 7.3 权限好像失效了（点不动、截图黑屏/报错）

- 先分清症状：点不动、打不了字 → 辅助功能；截图黑屏或拿不到图 → 屏幕录制；
- 回系统设置两个列表里确认：**带三角图标的 Can** 开关是开的
  （开错成黑图标的旧文件条目等于没开）；
- 屏幕录制的条目如果根本不在列表里，引擎申请加不进去，
  用第 2.3 步的办法点「＋」选 Can.app 手动加；
- **改完任何权限都要重启 agent 才生效**；
- 如果最近动过 Can.app 包里的文件（加了、改了、重新打包了），
  它的签名指纹变了，旧授权全部作废——把包恢复原状，或者按 2.3 重走一遍授权。

### 7.4 登录项里 Can 的图标是黑的

已知现象，不用管：系统设置「登录项 → 后台 App 活动」那一列是按启动文件取图标的，
Can 的条目走的是启动配置文件，所以显示一个黑色的默认图标；
而隐私权限那两张列表里显示的是正确的三角图标。
它只是不好看，**不影响任何功能**——不要为了这个图标去动 Can.app 的包，
一动包，权限又要重来（见 7.3）。

### 7.5 服务器重启了 / 被换了

- 如果你按第 1 步的加固装了看门狗，它会在一两分钟内把网关和隧道重新拉起，
  Mac 上的 agent 会自己重连，什么都不用做（2026-11-06 实证过一次）；
- 没有看门狗的话，手动 `systemctl start can-gateway` 和你的隧道服务即可；
- 注意 ngrok 免费域名的地址是固定的，重启不会变；如果哪天地址变了，
  agent 的 `config.json` 和各家连接器里的地址都要跟着改。

### 7.6 ego 那层打开网站是未登录状态

任务空间建错了浏览器配置：Can 的任务空间要建在你**日常在用的那个配置**下
才会继承登录；建在默认/其他配置下就是干净的未登录状态。与浏览器窗口开没开无关。
